🧱 FFmpeg: The Essential Foundation

O FFmpeg is the tool that cuts and renders video behind the scenes—it’s the foundation of Remotion, which Hyperframes uses to assemble the motion. It’s only truly required item in the core: without it, nothing runs. Installation varies a little by operating system.

Objective: install FFmpeg on your system. Choose the line for your OS (the others are commented out with #) and paste it into the terminal.

terminal · install FFmpeg 
# macOS (Homebrew)
brew install ffmpeg

# Ubuntu / Debian
sudo apt update && sudo apt install -y ffmpeg

# Windows (PowerShell, com winget)
winget install --id Gyan.FFmpeg -e

How to verify

Run the command below. A line starting with should appear ffmpeg version .... If you see "command not found," reopen the terminal (or the session) and try again.

ffmpeg -version
What it is

The editing and rendering tool that Remotion/Hyperframes is built on.

Why learn

It’s the only truly required item; without it, nothing runs.

Key concepts

FFmpeg, rendering, system dependency.

2

⚙️ Hyperframes: the motion engine

O Hyperframes is the second essential component: it’s the engine that assembles the reel’s animations (motion graphics)—text that comes in with punch, chips, reveals. It runs via npx, so there’s no need for a heavyweight installation; the command itself downloads and runs it on the spot.

New here? — “npx”

npx is a shortcut that comes with Node.js: it runs a package without you installing it permanently. The first time, it may download a few files—that’s normal and only happens once.

Objective: confirm that Hyperframes responds on your machine.

terminal · check Hyperframes 
npx hyperframes --version

How to verify

The command should print a version number (something like 2.x.x). If it asks to install the package the first time, accept. If you get an error with npx not found; install Node.js first.

What it is

The engine that builds the reel’s motion, running via npx.

Why learn

Without it, there are no motion graphics; one command confirms it's up.

Key concepts

Hyperframes, npx, motion graphics.

3

🧠 Groq: The Review That Makes Up the Least

O Groq is free and highly recommended for the transcription (caption baseline) and for the review — in practice, it’s what “invents” the least for this task. You don’t need to install anything: just have the API key available as environment variable call GROQ_API_KEY.

Objective: check whether the key is already in the environment and, if not, set it. Replace the example value with your actual key.

terminal · GROQ_API_KEY 
# 1) já está definida? (deve imprimir a chave)
printenv GROQ_API_KEY

# 2) se não imprimiu nada, defina (troque pela sua chave)
export GROQ_API_KEY="<sua-chave-gsk_...>"

How to verify

After the export, run printenv GROQ_API_KEY again: now it should print your key (starting with gsk_). To avoid repeating this in every session, add the export in your ~/.bashrc or ~/.zshrc.

Why learn: an empty environment variable is the most common silent error here—the reel runs, but the captions come out worse. Checking first prevents rework. Key concepts: Groq, GROQ_API_KEY, environment variable.

4

➕ Optional: fal.ai, Firecrawl, /watch

These three aren’t required — you enable only what your profile calls for, and nothing paid goes in without your "yes". If anything is missing, the engine degrades gracefully instead of getting stuck.

🖼️

fal.ai (AI-generated image · paid)

Generates images for cold opens and inserts. Since it’s paid, it’s only used if you explicitly approve.

🌐

Firecrawl (real B-roll · free)

Brings in real screenshots of the sites/repositories you mention, for use as actual B-roll instead of generic imagery.

👁️

/watch (visual QC)

Performs quality control by looking at the reel’s frames — helps the reviewer catch gaps and overlaps.

Objective: if your profile requires fal.ai and/or Firecrawl, set the keys (opt-in). Skip the ones you won't use.

terminal · optional keys 
# só se o seu perfil usar imagem por IA (pago)
export FAL_KEY="<sua-chave-fal>"

# só se o seu perfil usar B-roll real (grátis)
export FIRECRAWL_API_KEY="<sua-chave-firecrawl>"

How to verify

Confirm with printenv FAL_KEY or printenv FIRECRAWL_API_KEY. Didn't define any? No problem—the environment check (module 3.2) will only ask for what your profile actually needs.

Key concepts: fal.ai, Firecrawl, /watch, opt-in (you approve before enabling).

5

📦 Install the .skill

With the stack in place, all that’s left is to load the meta-skill in Claude. The file has the extension .skill. There are two paths—use whichever is simplest for you.

⬇️ Download forja-reel.skill

The file (and the user guide) lives in the repo videos-edit-cria.

Path A — double-click

After downloading, run double-click in the file forja-reel.skill. Claude recognizes it and offers to load the skill.

Path B — through connectors

  1. Open the Claude.
  2. Go to connectors → skills.
  3. Choice load skill and point to the .skill.

How to verify

The skill for Reel Forge available. If it didn’t appear, make sure you downloaded the entire file (not the page) and repeat Path B.

Key concepts: .skill file, connectors, load skill.

6

▶️ Activate with "Forja Reel" and use Opus

Skill loaded, just call it. You activates the meta-skill by typing "Forge Reel" in the conversation with Claude. One detail that makes a difference: use the model Opus, not Sonnet — the interview and identity decisions are much more consistent.

Objective: start the meta-skill. With Opus selected in Claude, send this message.

Claude (model: Opus) · message 
Forja Reel

How to verify

The skill responds by starting the interview — the first question from the 8 sections appears. If you get a generic response instead, confirm that the skill is loaded (topic 5) and that you typed its exact name.

Why Opus and not Sonnet

The interview asks you to think through good identity choices and put together the perfil.json. The strongest model guides this conversation better and makes fewer mistakes in its decisions—it's worth switching before you start.

Key concepts: activation, Opus, interview. In module 3.2, we’ll go into the interview in detail.
